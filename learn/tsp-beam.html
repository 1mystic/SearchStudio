Beam search

Run it step by step

Hill climbing follows one path. Beam search keeps a few of the best candidates at each level, a beam of width w, so a slightly worse option that leads somewhere better is not thrown away immediately.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

OPEN holds w tours. Each level, generate the neighbours of all tours in OPEN, keep the w best as the new OPEN, and stop when the best of the level is no better than the best seen before.

02Pseudocode

OPEN ← [start];  N ← start
do
    bestEver ← N
    neighbours ← MoveGen(OPEN)        # of every node in OPEN, duplicates merged
    OPEN ← the w best of neighbours
    N ← head(OPEN)
while cost(N) < cost(bestEver)
return bestEver

03Line by line

OPEN ← [start]
neighbours ← MoveGen(OPEN)Neighbours of every member, with duplicates merged.
OPEN ← the w best of neighboursThis is the beam.
N ← head(OPEN)Best tour of the level.
while cost(N) < cost(bestEver)Stop when the level brings no improvement.

04Formulas and why they hold

memory = w, work per level ≈ w · |N|

width times neighbourhood size

Beam search trades memory for robustness; w = 1 is hill climbing, w = ∞ approaches breadth-first search.

05Why it works, and when it does not

Keeping alternatives lets the search survive one bad step. A narrow beam can still miss the path to the optimum; a wide one costs more.

06Properties

completeno
optimalno
timew · |N| per level
spaceO(w)

07Traps

  • w = 1 behaves exactly like hill climbing.
  • Merge duplicate tours when generating neighbours of several beam members.
  • Stopping is on the level's best, not on any member improving.
