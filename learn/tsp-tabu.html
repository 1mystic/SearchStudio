Tabu search

Run it step by step

Tabu search always moves, even downhill, to escape local optima. To avoid simply stepping back to where it came from, it keeps a short-term memory of recent moves that are forbidden (tabu) for a few iterations.

01Definition

At each iteration, move to the best neighbour whose move is not tabu. Mark that move tabu for tt iterations (the tenure). A tabu move is allowed anyway if it gives a tour better than any seen (aspiration). Return the best tour seen.

02Pseudocode

N ← start;  bestSeen ← N
repeat for k iterations
    candidates ← MoveGen(N), best first
    pick the first candidate that is not tabu,
         or is tabu but better than bestSeen (aspiration)
    make its key tabu for tt iterations
    N ← candidate;  if N better than bestSeen: bestSeen ← N
return bestSeen

03Line by line

N ← start; bestSeen ← N
candidates ← MoveGen(N), best first
first candidate that is not tabu (or beats bestSeen)This can be worse than N: that is how tabu escapes local optima.
make its key tabu for tt iterationsHere the key is the swapped pair of cities.
N ← candidate; update bestSeenReturn bestSeen at the end.

04Formulas and why they hold

tabu(m) ⇔ t < expiry(m), expiry(m) = t(used) + tt

a move stays forbidden for tt iterations

Short tenure risks cycling; long tenure can block good moves.

aspiration: allow m if cost(m(N)) < cost(bestSeen)

a forbidden move is fine if it finds a new best

Tabu exists to stop cycling, not to block real improvements.

05Why it works, and when it does not

Memory turns a greedy walk into a systematic one. On small instances a short tenure leads to cycles; a frequency memory (prefer rarely-used moves) further diversifies the search.

07Traps

  • Tabu takes the best non-tabu move even if it is worse than the current tour.
  • Apply aspiration before rejecting a tabu move.
  • Return bestSeen, not the final current tour.
