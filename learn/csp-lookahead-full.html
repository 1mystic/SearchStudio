Week 12 · Constraint processing · lookahead

Full look-ahead

Run it step by step

Look-ahead methods reason about the future variables after every assignment, so that dead ends are found one or more levels earlier. Forward checking only compares the variable just assigned with its future neighbours; the look-ahead methods also compare the future variables with each other.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

After assigning Xᵢ = a: (1) forward checking, then (2) forward checking, then every arc between two future variables is revised once, in both directions. If any future domain becomes empty, reject a at once. This is the "Full look-ahead" variant: one pass over all future arcs.

02Pseudocode

Lookahead(assignment, domains, i):          # mode = full
    if i > n: return assignment
    for each value a in D(Xᵢ)
        D' ← copy of domains;  D'(Xᵢ) ← {a}
        forward check: prune D'(Y) of every unassigned neighbour Y against Xᵢ = a
        extra look-ahead (one pass over all future arcs):
            revise the future variables against each other
        if no D'(Y) is empty: result ← Lookahead(assignment + {Xᵢ = a}, D', i + 1); if result: return it
    return failure

04Formulas and why they hold

D(Y) ← { b ∈ D(Y) : ∃ c ∈ D(Z), (b, c) allowed by C(Y,Z) }

delete values of a future variable Y that have no support in another future variable Z

A value without support can never be part of a solution extending the current assignment, so deleting it is safe.

05Why it works, and when it does not

A future variable can be squeezed empty by two OTHER future variables. Forward checking cannot see that until one of them is assigned; look-ahead sees it now. Example: after G = W the neighbours of G lose W and become single-valued, which empties D(E); only the look-ahead variants notice (see the example 'G = W wipes out E').

06Properties

completeyes
optimaln/a
timeO(dⁿ) worst case, smaller tree than forward checking
spaceO(n·d) for domain copies

07Traps

  • The three variants prune in a strict order: forward checking < partial < full < MAC (each prunes at least what the previous one does). Example 'Look-ahead ladder' shows 17, 6, 5 and 3 values tried before the same conclusion (no solution).
  • Partial look-ahead depends on the variable order: a variable that is last in the ordering is never revised against anything, so it may miss a wipe-out that full look-ahead finds.
  • More pruning per node does not always mean less total time; each node costs more.
  • Which pruning came from forward checking and which from the extra look-ahead is shown in separate columns. The split into 'partial / full / MAC' passes is the usual textbook presentation; the exact pass structure is **supplementary** to the lecture slides.
