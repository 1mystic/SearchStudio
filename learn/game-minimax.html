Week 7 · Game playing

Minimax

Run it step by step

In a two-player game one player (MAX) wants a high score and the other (MIN) a low one. Minimax looks ahead to the end of the tree and assumes both play perfectly: MAX picks the child with the largest value, MIN the smallest.

01Definition

Evaluate leaves with the evaluation function e. Back values up the tree: a MAX node's value is the maximum of its children, a MIN node's value is the minimum. The root's value is the guaranteed outcome.

02Pseudocode

Minimax(N):
    if N is a leaf: return e(N)
    if N is MAX: return max over children C of Minimax(C)
    if N is MIN: return min over children C of Minimax(C)

03Line by line

leaf: return e(N)The static evaluation from MAX's point of view.
MAX node: max of childrenMAX chooses the move that is best for MAX.
MIN node: min of childrenMIN chooses the move that is worst for MAX.

04Formulas and why they hold

v(N) = max over C of v(C) at MAX, min over C of v(C) at MIN

back up the best reply at every level

Assuming the opponent replies optimally, this is the best value MAX can guarantee.

05Why it works, and when it does not

Correct but exhaustive: it evaluates every leaf, b^d of them.

06Properties

completeyes (finite tree)
optimalyes against an optimal opponent
timeO(b^d)
spaceO(b·d)

07Traps

  • Values are always from MAX's point of view.
  • Evaluate left to right; the order matters for alpha-beta, not for minimax.
