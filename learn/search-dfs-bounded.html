Depth-Bounded DFS

Run it step by step

Depth-bounded DFS is plain Depth First Search with a ceiling on depth. A node at the bound is tested but never expanded, so the search cannot dive forever down one branch.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

OPEN is a stack of node pairs (N, parent, depth). The start node has depth 0 and a child has depth(parent)+1. When the node taken from OPEN has depth equal to the bound, it is goal-tested but no children are generated. If OPEN empties without reaching the goal, there is no goal within the bound (the search is incomplete: a deeper goal is not ruled out).

02Pseudocode

OPEN ← [(S, nil, 0)];  CLOSED ← [ ]
while OPEN not empty
    (N, parent, d) ← head(OPEN);  remove it
    if GoalTest(N): return the path
    CLOSED ← (N, parent, d) : CLOSED
    if d < depthBound:
        children ← MoveGen(N) minus nodes on OPEN or CLOSED
        OPEN ← [(C, N, d+1) for C in children] ++ OPEN     # stack
return failure   (no goal within the bound)

03Line by line

OPEN ← [(S, nil, 0)]The start node has depth 0.
(N, parent, d) ← head(OPEN)Newest entry first (stack).
if GoalTest(N): returnThe goal test happens when a node is picked.
if d < depthBound: expandNodes at the bound are not expanded.
children get depth d + 1They go to the front of OPEN.

04Formulas and why they hold

depth(C) = depth(N) + 1

a child is one level deeper

Depth is what the bound limits.

expand N only if depth(N) < bound

stop generating at the ceiling

This guarantees every branch has finite length, so the search terminates.

05Why it works, and when it does not

It is the building block of DFID: run it with bound 0, 1, 2, … to get the completeness of BFS with the memory of DFS. On its own it is incomplete, and the path it finds is not guaranteed to be shortest.

06Properties

completeno (only if the goal is within the bound)
optimalno
timeO(b^bound)
spaceO(b·bound)

07Traps

  • A bound that is too small fails even though a goal exists: failure only means no goal within the bound (graph-dfs-deep: bound 2 fails, bound 3 finds the goal at depth 3).
  • Even a bound that is large enough can fail with a CLOSED list: a node first reached by a long route is closed at the bound and a later short route to it is skipped (graph-dfid-closed, bound 3 fails; DFID succeeds there because it reopens such nodes).
  • A bound that is too large behaves like plain DFS and can find a long, winding path.
  • The goal test applies to nodes at the bound too; only their expansion is skipped.
