Genetic algorithm

Run it step by step

A genetic algorithm keeps a whole population of candidate assignments instead of a single one. Fitter strings (more clauses satisfied) are more likely to become parents; crossover mixes the bits of two parents and mutation occasionally flips a bit, which can create strings that neither parent could.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Fitness of a string is h, the number of satisfied clauses. Selection probability is p = h / Σh (roulette wheel: the cumulative probabilities partition [0, 1) and a uniform u picks the interval it falls in). Pairs of selected parents are crossed at a random one-point cut, and each child is mutated with probability pm by flipping one random bit.

02Pseudocode

Pop ← N bit strings (given, or random)
repeat for g generations
    fitness(x) ← h(x);   p(x) ← h(x) / Σ h
    pool ← N strings drawn by roulette-wheel (spin u, take the first x with cumulative p ≥ u)
    for each consecutive pair (a, b) of the pool
        cut ← random point in 1..n−1;   children ← a[0..cut)+b[cut..), b[0..cut)+a[cut..)
        with probability pm flip one random bit of each child
    Pop ← the children
return the best string ever seen

03Line by line

fitness(x) ← h(x)The population table shows h and the selection probability of each member.
spin the wheel N timesEach spin draws u from the seeded generator and picks the member whose cumulative interval contains u: fit members can be picked several times, weak ones not at all.
one-point crossoverPick a cut between two bits; each child takes the left part of one parent and the right part of the other.
mutation with probability pmA random bit of the child is flipped. This is how new bit values can appear that the population does not contain.
Pop ← childrenA complete replacement of the generation (no elitism); the best string ever seen is tracked separately.

04Formulas and why they hold

p(xᵢ) = h(xᵢ) / Σⱼ h(xⱼ)

selection probability proportional to fitness

The probabilities sum to 1, and a string with twice the fitness gets twice the share of the wheel.

cumulative cᵢ = p(x₁) + … + p(xᵢ)

the wheel's boundaries

u falls in the interval (cᵢ₋₁, cᵢ] of exactly one member, so the draw has the right probabilities.

05Why it works, and when it does not

Crossover recombines good partial assignments, mutation keeps diversity. On the course example a single generation can produce the solution 1101 when mutation flips the right bit of a child that is one flip away from it. The method is incomplete: with few generations or a tiny population it may never find a solution.

07Traps

  • Crossover only recombines bit values already present in the population; only mutation creates new ones. Default population 1000,0110,0011,1100, 1 generation: with pm = 0.5 and seed 9 the solution 1101 is made by mutation (child 1100 mutated at d); with pm = 0 and seed 1 it is made by crossover alone (1100 × 0011 cut after c gives 1101). With the population 1000,0110,1100,0100, where every string has d = 0, pm = 0 can never produce 1101 however many generations you run, while pm = 0.5 usually finds it.
  • Fitness-proportional selection is weak when all h values are close: the probabilities are then almost equal.
  • If every h is 0 the wheel would divide by zero; the trace falls back to uniform probabilities.
  • A solution found in a child must be recorded when it appears: the next generation may lose it.
  • Results depend on the seed and on the initial population; the same inputs repeat the run exactly.
