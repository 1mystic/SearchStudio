Brute force (exact)

Run it step by step

The travelling salesperson problem (TSP) asks for the shortest round trip that visits every city exactly once. Brute force simply tries every possible round trip and keeps the shortest. It is the only method here that is guaranteed to find the best tour, and it is how every other method's answer is checked.

01Definition

Fix the first city (a round trip can start anywhere), list every ordering of the remaining n−1 cities, compute each tour's cost, and return the cheapest.

02Pseudocode

best ← ∞
for every permutation p of cities 2..n   (symmetric: skip p with p[first] > p[last])
    if cost(city1 + p) < best: best ← that tour
return best

03Line by line

best ← ∞No tour seen yet.
for every permutation p of cities 2..nThere are (n−1)! orderings. In a symmetric TSP a tour and its reverse cost the same, so only half are distinct.
if cost(city1 + p) < bestCost = sum of the n edges, including the edge back to the start.
return bestThe cheapest tour is the optimum.

04Formulas and why they hold

number of tours = (n−1)! / 2 (symmetric)

fix one city, order the rest, halve for direction

Rotations of a cycle are the same tour, and so is the reversed cycle when C(i,j) = C(j,i).

cost(T) = Σ C(tᵢ, tᵢ₊₁) + C(tₙ, t₁)

add up every edge on the cycle

The closing edge back to the start is part of the tour; forgetting it is the most common arithmetic slip.

05Why it works, and when it does not

It works because it leaves nothing out. It fails in practice because (n−1)!/2 explodes: 60 tours for 6 cities, 181,440 for 10, about 10^155 for 100.

06Properties

completeyes
optimalyes
timeO(n!)
spaceO(n)

07Traps

  • Forgetting the closing edge.
  • Counting (n−1)! instead of (n−1)!/2 for a symmetric instance.
  • Using brute force on large n: the studio limits it to 9 cities.
