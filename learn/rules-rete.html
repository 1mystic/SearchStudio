Week 10 · Rule-based systems

Rete algorithm

Run it step by step

Most cycles of a rule system change only a few facts, yet naive matching re-checks every rule against everything. The Rete algorithm compiles the rules into a network that remembers partial matches, so each new fact is matched only where it matters.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Alpha nodes test single patterns and store matching facts. Beta (join) nodes combine a stored partial match (token) from the left with a fact from the right when their variable bindings agree, and pass the result on. Terminal nodes add complete matches to the conflict set. Rules that share leading patterns share nodes.

02Pseudocode

compile: one alpha memory per distinct pattern;
         for each rule a chain of join nodes (shared when rules start with the same patterns) ending in a terminal
add fact w:
    for each alpha memory whose pattern matches w: store w, then
        right-activate its join nodes: combine w with each token in the left memory whose bindings agree
        each new token goes to the next join node, or to the terminal → add the instantiation to the conflict set
fire instantiations (rule order); each new fact is added the same way

03Line by line

compile the rulesOne alpha memory per distinct pattern; a chain of joins per rule, shared where prefixes coincide.
add a factIt enters the alpha memories it matches.
joinCombine with stored tokens that agree on shared variables.
terminalA complete token is a rule instantiation.

04Formulas and why they hold

work per new fact ∝ affected tokens, not |rules| × |WM|

incremental matching

Stored partial matches mean old facts are never matched again.

05Why it works, and when it does not

Trades memory (all partial matches) for speed, which made large production systems practical.
