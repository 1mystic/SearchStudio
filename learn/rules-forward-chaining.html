Week 10 · Rule-based systems

Forward chaining

Run it step by step

A rule-based system holds facts in working memory and knowledge as if–then rules. Forward chaining starts from the facts and keeps firing rules whose conditions match until nothing new can be derived.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

The recognise–act cycle: match all rules against working memory to form the conflict set of rule instantiations; resolve the conflict by choosing one (rule order, recency, specificity); execute its actions; repeat. A fired instantiation is not fired again (refractoriness).

02Pseudocode

repeat
    MATCH:   conflict set ← every (rule, bindings) whose conditions hold in WM and that has not fired
    if the conflict set is empty: stop
    RESOLVE: pick one by the strategy (rule order, recency or specificity)
    EXECUTE: apply its actions to WM (add / remove facts); remember it fired (refractoriness)

03Line by line

MATCHFind every way to bind each rule's variables to facts.
RESOLVEChoose one instantiation by the strategy.
EXECUTEAdd or remove facts.
stop when the conflict set is empty

04Formulas and why they hold

instantiation = (rule, variable bindings)

a rule with its ?variables filled in consistently

The same rule can fire several times with different bindings.

05Why it works, and when it does not

Data-driven reasoning, natural for monitoring and configuration. Naive matching repeats work each cycle; Rete removes that cost.

06Properties

completederives every consequence (add-only rules)
optimaln/a
timematch cost per cycle
spaceWM + conflict set

07Traps

  • A variable must bind to the same value in every condition of a rule.
  • Conflict resolution changes the order, not the final set of derived facts (for rules that only add).
