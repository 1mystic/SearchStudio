Hill Climbing

Run it step by step

Hill climbing is the simplest way to use a heuristic: always step to the neighbour that looks closest to the goal, and stop when no neighbour looks better than where you are. It needs almost no memory, but it can stop on a hilltop that is not the summit.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

From the current node move to the child with the smallest h, provided it is strictly smaller than h(current). Otherwise stop and return the current node.

02Pseudocode

node ← start
newNode ← head(sort_h(MoveGen(node)))
while h(newNode) < h(node)
    node ← newNode
    newNode ← head(sort_h(MoveGen(node)))
return node

03Line by line

node ← start
newNode ← best child by hOnly the children of the current node are compared.
while h(newNode) < h(node)Strict improvement is required; equal h means a plateau and the search stops.
return nodeThis is a local optimum of h; it is the goal only if h(goal) is the only minimum reached.

04Formulas and why they hold

next = argmin over children C of h(C), accepted only if h(next) < h(current)

go to the best-looking child only if it is better than here

Greedy local improvement; there is no memory to back up from a dead end.

05Why it works, and when it does not

Constant memory and very fast, but incomplete: local optima, plateaus and ridges stop it. The fixes are exactly the Week 3 ideas: beam search, random restarts, tabu memory, simulated annealing.

07Traps

  • Hill climbing never backtracks.
  • A plateau (equal h) stops the course version.
  • Reaching a node with h = 0 that is not the goal means h is misleading there.
