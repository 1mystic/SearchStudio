Nearest Neighbour

Run it step by step

Nearest Neighbour is what most people do by hand: from where you are, go to the closest place you have not visited yet. It builds a tour quickly but can paint itself into a corner and pay for a long trip home at the end.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A constructive (synthesis) heuristic: start at a given city, repeatedly append the nearest unvisited city, and finally return to the start.

02Pseudocode

tour ← [start]
while unvisited cities remain
    c ← last city of tour
    append the unvisited city nearest to c   (ties: alphabetical)
return tour   (closing edge back to start is implied)

03Line by line

tour ← [start]The path starts at the chosen city.
while unvisited cities remainn−1 choices are made in total.
c ← last city of tourOnly the current end of the path matters: NN never looks back.
append the unvisited city nearest to cTies go to the alphabetically first city (the course convention).
return tourThe edge from the last city back to the start is forced, whatever its length.

04Formulas and why they hold

next = argmin over unvisited j of C(c, j)

pick the cheapest edge out of the current city that leads somewhere new

Each choice is locally best; nothing guarantees the sum of choices is globally best.

NN ≤ ½(⌈log₂ n⌉ + 1) · OPT (metric TSP)

in the worst case NN can be about log n times worse than optimal

Bad cases exist where greedy local moves strand far-away cities.

05Why it works, and when it does not

Cheap and intuitive. Its weakness is the end game: the last cities are whatever is left over, often far apart, and the forced return edge can be the longest edge in the tour.

06Properties

completealways returns a tour
optimalno
timeO(n²)
spaceO(n)

07Traps

  • The tour depends on the start city: run it from every city and keep the best.
  • Do not forget the forced return edge in the cost.
  • Write the answer in path representation starting from the asked city.
