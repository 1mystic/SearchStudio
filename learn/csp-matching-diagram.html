Week 11 · Constraint processing

Matching diagram and arc consistency

Run it step by step

A constraint is a relation: the set of value pairs it allows. The matching diagram draws that relation as lines between two columns of dots, so that 'this value has a supporting value in the neighbour' becomes 'this dot has at least one line going to the neighbouring column'. Arc consistency is then just: remove dots with no line, and keep going while that orphans more dots. **Supplementary:** the matching-diagram drawing is a teaching picture of the course's arc consistency, not a separate algorithm.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

For a binary CSP, a matching diagram has one column per variable, one dot per value in its domain, and a line between (X = a) and (Y = b) exactly when the constraint between X and Y allows the pair (a, b). Revise(X, Y) deletes every dot of column X that has no line to a live dot of column Y. Repeating Revise over all arcs (AC-3) until nothing changes gives arc consistency.

02Pseudocode

for each variable X: draw a column with one dot per value in D(X)
for each constraint C(X, Y): join (X = a) and (Y = b) by a line when (a, b) is allowed
AC-3 on the diagram:
    Q ← every arc (X, Y)
    while Q not empty
        (X, Y) ← pop(Q)
        for each dot (X = a) with no line to any live dot of column Y: delete it
        if something was deleted: add every arc (Z, X), Z ≠ Y, to Q

03Line by line

draw columnsOne dot per value of each domain.
draw lines of each constraintA line means the pair is allowed; no line means forbidden.
Revise(X, Y)Look for dots in column X that have no line into column Y.
delete an unsupported dotIts lines disappear too, which can leave dots in other columns with no support.
requeue arcs (Z, X)Only neighbours of a changed column can lose support.

04Formulas and why they hold

a ∈ D(X) survives Revise(X, Y) ⇔ ∃ b ∈ D(Y): (a, b) ∈ R(X, Y)

a dot survives if it has a line to some live dot in the neighbouring column

In any solution with X = a the variable Y takes some value b of its domain, and the pair must be allowed; with no such b the value a can never be part of a solution.

lines(X, Y) = { (a, b) : (a, b) allowed by C(X, Y) }

the relation drawn as lines

Lines make the relation visible: a constraint like X < Y over {1,2,3} has 3 lines, and the dots 3 (in X) and 1 (in Y) have none.

05Why it works, and when it does not

The picture explains why arc consistency solves the ordering chain (dots peel away like dominoes) and does nothing on map colouring (every dot keeps a line to every neighbouring column).

06Properties

completeno (filtering only)
optimaln/a
timeO(e·d³)
spaceO(n·d + lines)

07Traps

  • A dot needs a line to at least one live dot of the neighbouring column, not to all of them.
  • Lines to a deleted dot no longer count; that is why deletions cascade.
  • Arc consistency can leave several dots in every column and still have no solution (compare Path consistency on the two-colour triangle).
