Week 8 · Planning

Backward state-space planning

Run it step by step

A planning problem gives an initial state, a goal and operators described in STRIPS form: each operator has preconditions, an add list and a delete list. In the blocks world the operators are pickup, putdown, stack and unstack, and AE means the arm is empty. Backward planning starts from the goal and asks which action could have achieved it last.

01Definition

Search over goal sets. An operator is relevant if it adds at least one goal and deletes none. Regressing goal set G through it gives (G − add) ∪ pre. Stop when the initial state satisfies the goal set.

02Pseudocode

OPEN ← [(goal, plan = [ ])]
while OPEN not empty
    (G, plan) ← head(OPEN)
    if G ⊆ init: return plan
    for each operator O that adds some g ∈ G and deletes nothing in G
        G' ← (G − add(O)) ∪ pre(O)
        if G' is consistent and new: append (G', [O] + plan)

03Line by line

G ← goal
relevant operators onlyMust add something in G and delete nothing in G.
G' = (G − add) ∪ preWhat must be true before the action so that G holds after it.
stop when G ⊆ initial stateThe plan is the sequence of operators, read forwards.

04Formulas and why they hold

regress(G, O) = (G − add(O)) ∪ pre(O)

goals the action achieves are dropped, its preconditions are added

These are exactly the facts needed before O so that G holds after O.

05Why it works, and when it does not

Focused on the goal, so the branching factor is small, but goal sets can be impossible (like holding a block with the arm empty) and must be pruned.

06Properties

completeyes
optimalshortest plan (BFS)
timeO(b^d) with smaller b
spaceO(b^d)

07Traps

  • Discard inconsistent goal sets.
  • An operator that deletes a goal cannot be the last step.
