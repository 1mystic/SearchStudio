Divide & Conquer Frontier Search

Run it step by step

Most of A*'s memory is the CLOSED list, kept only to avoid regenerating expanded nodes and to rebuild the path. Frontier search drops CLOSED altogether; Divide and Conquer Frontier Search then rebuilds the path from a node remembered halfway along it.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Run best-first search keeping only OPEN. Each OPEN node records which neighbours already used an edge into it, so expanded nodes are never regenerated. Each node also carries a relay node from the middle of its path. Once the goal is reached, solve start→relay and relay→goal the same way, recursively.

02Pseudocode

DCFS(S, G):
    run frontier search from S to G           # OPEN only; each node keeps a 'used' set of neighbours
        each node carries relay = the first node on its path with g ≥ C/2   (C = estimate f(S))
    if G is next to S: return [S, G]
    R ← relay of G
    return DCFS(S, R) ++ DCFS(R, G)       # (dropping the repeated R)

03Line by line

OPEN only, with 'used' edge setsInstead of CLOSED, the frontier node remembers the edges already used.
relay ← first node with g ≥ C/2C is estimated as f(start).
solve start→relay and relay→goalEach half is a smaller problem; the recursion rebuilds the full path.

04Formulas and why they hold

memory ≈ |frontier|, not |frontier| + |expanded|

only the boundary of the search is stored

For grid-like spaces (such as sequence alignment) the frontier is much smaller than the expanded region.

05Why it works, and when it does not

Trades extra time (the recursive searches) for a large memory saving. It is the basis of memory-efficient sequence alignment.

06Properties

completeyes
optimalyes with admissible h
timea small multiple of one search
spacefrontier only

07Traps

  • Frontier search alone gives the cost, not the path: the relay recursion recovers it.
  • The 'used' bookkeeping is what replaces the CLOSED check.
