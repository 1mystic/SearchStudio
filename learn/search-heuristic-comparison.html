Week 5 · Graph search · optimal

Heuristic comparison (A* with h = 0, h, h*)

Run it step by step

The quality of a heuristic shows in how much search it saves. Here the same graph is searched by A* with three heuristics: no information (h = 0), the given h, and the perfect h = h*, the true remaining cost.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A* orders OPEN on f = g + h. With h = 0 it expands nodes in order of g, which is Uniform Cost Search. With h = h* (the exact cost to the goal, computed by Dijkstra from the goal) f is constant along an optimal path, so only that path is expanded (up to ties). An admissible h lies between the two: h ≤ h*, and a larger h (closer to h*) never expands more nodes than a smaller admissible one, apart from ties. **Supplementary:** the effective branching factor b* is not part of the lecture notation; it is the b that makes a uniform tree of depth d (the solution length) hold exactly as many nodes as were generated, 1 + b* + … + b*^d = generated. A smaller b* (closer to 1) means a better heuristic.

02Pseudocode

for each heuristic H in [ h = 0,  h (given),  h = h* ]:
    run A* with f = g + H
    record: nodes expanded, nodes generated, path cost
    b* ← the branching factor of a uniform tree of depth d (solution length)
         with the same number of nodes:   generated = 1 + b* + b*² + … + b*^d
compare the three rows

03Line by line

A* with h = 0The baseline: Uniform Cost Search.
A* with the given hHow much the problem's heuristic helps.
A* with h = h*The best any heuristic can do: expand only the solution path.
compare expansions and b*Fewer expansions and b* near 1 mean a more informed heuristic.

04Formulas and why they hold

0 ≤ h ≤ h* ⇒ expansions(h*) ≤ expansions(h) ≤ expansions(0)

a more informed admissible h expands no more nodes (up to ties)

A* expands every node with f < C*; raising h raises f and removes nodes from that set.

generated = 1 + b* + b*² + … + b*^d

effective branching factor (supplementary)

It turns a node count into a single branching number that can be compared across problems.

05Why it works, and when it does not

It makes the value of heuristic information concrete. On an inadmissible h the middle row can be cheaper to run but return a worse path: the path cost column then differs from the other two.

06Properties

07Traps

  • Admissible does not mean good: h = 0 is admissible and almost useless.
  • With an inadmissible h the middle row may have a higher cost than the others (example 'Same graph, inadmissible h(B) = 12': 13 against 12).
  • Ties can make the counts differ by one or two; the ordering of the three rows is what matters.
  • h* needs the true remaining costs, which in practice means already having solved the problem.
