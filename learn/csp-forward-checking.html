Week 11 · Constraint processing

Forward checking

Run it step by step

A constraint satisfaction problem has variables, each with a domain of values, and constraints saying which combinations are allowed. A solution assigns every variable a value from its domain so that every constraint holds. Forward checking combines search with a little reasoning: it looks ahead after each assignment.

01Definition

After assigning X = a, remove from the domains of X's unassigned neighbours every value that conflicts with a. If a domain becomes empty, reject a immediately.

02Pseudocode

FC(assignment, domains, i):
    if i > n: return assignment
    for each value a in D(Xᵢ)
        D' ← copy of domains;  D'(Xᵢ) ← {a}
        for each unassigned neighbour Y: remove from D'(Y) values inconsistent with Xᵢ = a
        if no D'(Y) is empty: result ← FC(assignment + {Xᵢ = a}, D', i + 1); if result: return it
    return failure

03Line by line

assign X = a
prune neighbours' domainsOnly constraints between X and future variables are used.
empty domain → try the next valueThe dead end is found before descending.

04Formulas and why they hold

D(Y) ← { b ∈ D(Y) : (a, b) allowed by C(X,Y) }

keep only values compatible with the new assignment

Any value removed could never be part of a solution extending X = a.

05Why it works, and when it does not

Usually far fewer nodes than plain backtracking; pairs well with choosing the variable with the smallest remaining domain (MRV).

06Properties

completeyes
optimaln/a

  • Forward checking does not check two future variables against each other; arc consistency does.
