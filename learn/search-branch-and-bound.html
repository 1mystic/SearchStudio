Branch & Bound (state space)

Run it step by step

Branch & Bound explores a tree of paths, always refining the cheapest partial path. Nothing records which states have already been reached, so the same state can be generated again by a different path. This tracer shows how often each state occurs in the search tree.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Each OPEN entry is one partial path from S, stored as a node pair (node, parent, g). A refinement takes the cheapest entry and replaces it by its children, one per neighbour that is not already on that path (so a path never loops). There is no CLOSED list, so two different paths to the same state are both kept as separate tree nodes. The goal test is applied when the goal is picked from OPEN; its g is then the cost of the cheapest path, because every other entry on OPEN costs at least as much.

02Pseudocode

OPEN ← [(S, nil, g=0)]                      # a search TREE: no CLOSED list
repeat
    N ← node on OPEN with least g                # ties: alphabetical, then oldest
    remove N from OPEN;  count one refinement
    if GoalTest(N): return the path of N         # g(N) is the bound: nothing on OPEN is cheaper
    for each child C of N not already on N's own path
        add (C, N, g(N)+k(N,C)) to OPEN          # even if C already occurs elsewhere in the tree

03Line by line

children not on N's pathDuplicates of a state in other branches are not removed.

04Formulas and why they hold

g(C) = g(N) + k(N, C)

cost of the extended path

Each tree node carries the cost of its own path.

tree size = Σ occurrences(state)

every path prefix is a node

Without CLOSED, merging never happens, so the tree can be much larger than the graph.

05Why it works, and when it does not

It finds the optimal path like UCS, but because it does not merge duplicates it does more work. Adding a CLOSED list (and updating g on cheaper paths) turns it into Dijkstra's algorithm. The occurrence counts show exactly what a CLOSED list saves.

06Properties

completeyes (finite graph, no loops on a path)
optimalyes (non-negative costs)
timeexponential in the worst case
spaceall tree nodes

07Traps

  • Duplicates: on 'Graph T' A appears twice, B twice and G three times, while Dijkstra on the same graph closes each node once; on the 4×5 grid the tree has hundreds of nodes for 20 states.
  • The goal state may itself appear several times in the tree; only the first one picked ends the search.
  • Do not stop when the goal is generated: stop when it is picked.
  • A pick of a node is counted as a refinement even when it is the goal.
