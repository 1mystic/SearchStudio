Week 4 · Emergent systems

Game of Life: generation stepper

Run it step by step

The Game of Life is a grid of cells, each alive or dead. There is no player and no goal. Every cell applies the same tiny rule to its eight neighbours, all at the same moment, and patterns appear that nobody wrote down: blocks that never change, blinkers that flash, gliders that walk across the grid. It is the standard picture of an emergent system: global behaviour from simple local rules.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

State = the set of live cells. Next state: a live cell survives with 2 or 3 live neighbours (S23); a dead cell with exactly 3 live neighbours becomes alive (B3); everything else is dead in the next generation. The rule reads the old generation only, so the update is simultaneous.

02Pseudocode

repeat for each generation:
    for each cell, n ← number of live neighbours (of 8)
        if the cell is alive:  survives if n = 2 or n = 3, else dies   (S23)
        if the cell is dead:   is born if n = 3                         (B3)
    all cells change together: the new grid is computed from the old one
    population ← number of live cells

03Line by line

count the live neighbours of every cellOnly the eight surrounding cells matter. There is no other information.
live cell with 2 or 3 neighbours survivesS23: enough company to live, not enough crowding to die.
live cell with fewer than 2 or more than 3 neighbours diesLoneliness (underpopulation) or overcrowding.
dead cell with exactly 3 neighbours is bornB3: three parents make a new cell.
apply all changes at onceBirths and deaths in one generation never influence each other.

04Formulas and why they hold

next(c) = 1 if (alive(c) and n(c) ∈ {2, 3}) or (dead(c) and n(c) = 3), else 0

alive next time if it has the right number of neighbours

This is the whole rule, written as B3/S23: Birth on 3, Survival on 2 or 3.

population(t) = number of live cells in generation t

how many cells are alive

Plotted over time it shows growth, decay or a steady state (still lifes and oscillators) at a glance.

05Why it works, and when it does not

It shows that you can get rich behaviour without a plan or a controller, which is the core idea of emergent and self-organising systems. Gliders can even carry information, and the rule is rich enough to compute anything a computer can.

06Properties

completen/a (a simulation, not a search)
optimaln/a
timeO(cells) per generation
spaceO(cells)

07Traps

  • The update is simultaneous: do not use a cell's new state while counting another cell's neighbours.
  • A cell is not a neighbour of itself: a live cell counts only the other eight.
  • On a bounded grid cells beyond the edge count as dead (unless the grid wraps around), so patterns can behave differently near the border.
