Week 8 · Planning

Forward state-space planning

Run it step by step

A planning problem gives an initial state, a goal and operators described in STRIPS form: each operator has preconditions, an add list and a delete list. In the blocks world the operators are pickup, putdown, stack and unstack, and AE means the arm is empty. Forward planning simply searches the state space from the initial state.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Breadth-first search where a node is a state (a set of facts) and an edge applies an operator whose preconditions hold: S' = (S − delete) ∪ add.

02Pseudocode

OPEN ← [(init, plan = [ ])];  seen ← {init}
while OPEN not empty
    (S, plan) ← head(OPEN)
    if goal ⊆ S: return plan
    for each operator O with pre(O) ⊆ S
        S' ← (S − del(O)) ∪ add(O)
        if S' not seen: append (S', plan + [O])
return failure

03Line by line

start from the initial state
apply every applicable operatorPreconditions must all be true in the state.
S' = (S − del) ∪ addSTRIPS semantics: everything not deleted stays true.
stop when the goal facts all holdBFS gives a shortest plan.

04Formulas and why they hold

S' = (S − del(O)) ∪ add(O)

remove the delete list, add the add list

The STRIPS assumption: an action changes only what it explicitly says.

05Why it works, and when it does not

Simple and complete, but the branching factor is every applicable action, most of them irrelevant to the goal.

07Traps

  • Applicable is not the same as relevant: forward search wastes effort on irrelevant actions.
