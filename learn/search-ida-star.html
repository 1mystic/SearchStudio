Week 6 · Graph search · space saving

IDA*

Run it step by step

A* is optimal but can run out of memory because OPEN grows exponentially. IDA* gets the same answer using memory proportional to the path length, by running depth-first searches with a growing cost limit.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Repeat depth-first search from the start, refusing to go past any node whose f = g + h exceeds the current bound. The first bound is h(start); each next bound is the smallest f that was cut off in the previous pass.

02Pseudocode

bound ← f(S) = h(S)
loop
    t ← DFS(S, g = 0, bound)          # depth-first, nodes on the current path are not revisited
    if t = FOUND: return the path
    if t = ∞: return failure
    bound ← t                          # smallest f that exceeded the bound

DFS(N, g, bound):
    f ← g + h(N);  if f > bound: return f
    if GoalTest(N): return FOUND
    min ← ∞
    for each child C not on the path: t ← DFS(C, g + k(N,C), bound); if FOUND: return FOUND; min ← min(min, t)
    return min

03Line by line

bound ← h(start)With admissible h this cannot exceed the optimal cost.
DFS with f ≤ boundOnly the current path is stored; nodes already on the path are skipped to avoid cycles.
record the smallest f above the boundThat is the next bound: no solution can be cheaper than it.
repeat until the goal is reachedThe first goal found is optimal.

04Formulas and why they hold

bound₀ = h(S), boundₖ₊₁ = min { f(N) : f(N) > boundₖ }

raise the limit just enough to let in the next cheapest nodes

Never skipping a cost level means the first solution found is the cheapest.

f(N) = g(N) + h(N)

cost so far plus estimated remainder

Same evaluation as A*.

05Why it works, and when it does not

Optimal with admissible h and linear memory. It repeats work in every pass, which is cheap when f takes few distinct values and expensive when many nodes have different f.
