Week 7 · Game playing

Expectiminimax (supplementary)

Run it step by step

**Supplementary (Russell & Norvig): not in the course lectures.** In backgammon-like games a die roll lies between your move and the opponent's reply. Expectiminimax adds a third kind of node, the chance node, whose value is the average of its outcomes weighted by their probabilities.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Leaves hold e(N) for MAX. A MAX node backs up the maximum of its children, a MIN node the minimum, and a chance node the expected value Σ P(C)·v(C), where the probabilities on its outgoing edges sum to 1. The chance nodes do not change whose turn it is: in this studio a chance node sits between a player's move and the next player's node.

02Pseudocode

Expectiminimax(N):
    if N is a leaf: return e(N)
    if N is MAX:    return max over children C of Expectiminimax(C)
    if N is MIN:    return min over children C of Expectiminimax(C)
    if N is CHANCE: return Σ over children C of P(C) · Expectiminimax(C)

03Line by line

leaf: return e(N)The static value from MAX's point of view.
MAX node: max of children; MIN node: min of childrenAs in Minimax.
chance node: Σ probability × child valueThe outcome is not chosen by anyone, so we average over it.

04Formulas and why they hold

v(chance) = Σ over outcomes C of P(C) · v(C)

the expected value of the roll

Neither player controls the dice, so the best estimate of a position before the roll is its average over the outcomes.

05Why it works, and when it does not

Showing that values matter, not just their order: with chance nodes only the numbers (not merely which leaf is bigger) decide the move, so the evaluation function must be a proper scale. Alpha-beta and SSS* in this studio decline trees with chance nodes because their pruning rules assume pure MAX/MIN.

06Properties

completeyes (finite tree)
optimalmaximises expected value against an optimal opponent
timeO(b^d · n^d)
spaceO(b·d)

07Traps

  • A chance node's value can be a fraction that is not any leaf's value.
  • Probabilities on the edges of one chance node must sum to 1.
  • Treating chance nodes as MIN, MAX or a plain average gives a wrong value or a wrong move: the last caption on example game-chance-gamble lists them (4, 8 and 5 against the true 6.5).
  • Minimax would be wrong here: it treats the roll as a choice. Pruning is also harder, because an average is only bounded if the leaf values are.
