Breadth First Search

Run it step by step

Breadth First Search explores in rings: first everything one step from the start, then two steps, and so on. It finds the path with the fewest edges.

01Definition

A state-space search problem has a start node S, a goal test, and a MoveGen function that lists the neighbours of a node. The search keeps two lists: OPEN (nodes generated but not yet expanded) and CLOSED (nodes already expanded). Each entry is a node pair (node, parent, value) so the path can be read back through parents. BFS treats OPEN as a queue: new children go to the back.

02Pseudocode

OPEN ← [(S, nil, 0)];  CLOSED ← [ ]
while OPEN not empty
    (N, parent, d) ← head(OPEN);  remove it
    if GoalTest(N): return the path via parent pointers
    CLOSED ← (N, parent, d) : CLOSED
    children ← MoveGen(N) minus nodes on OPEN or CLOSED
    OPEN ← OPEN ++ [(C, N, d+1) for C in children]     # append = queue
return failure

03Line by line

OPEN ← [(S, nil, 0)]
(N, parent, d) ← head(OPEN)Oldest entry first (queue).
if GoalTest(N): return pathThe goal test is applied when a node is picked from OPEN, as in the course.
CLOSED ← (N, parent, d) : CLOSED
children not on OPEN or CLOSEDGraph search: seen nodes are not added again.
OPEN ← OPEN ++ childrenAppend = queue = breadth first.

04Formulas and why they hold

nodes ≈ b^d

branching factor to the power of the goal depth

BFS must hold an entire level of the tree in OPEN: memory, not time, is its bottleneck.

05Why it works, and when it does not

Complete on finite graphs and optimal when every edge costs the same. Uses a lot of memory.

06Properties

completeyes
optimalyes for unit costs
timeO(b^d)
spaceO(b^d)

07Traps

  • Optimal in number of edges, not in total cost when edge costs differ.
  • Children are added in MoveGen order (alphabetical here).
