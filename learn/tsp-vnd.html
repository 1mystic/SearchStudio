Variable neighbourhood descent

Run it step by step

If hill climbing gets stuck, one fix is to look further: use a bigger neighbourhood. Variable Neighbourhood Descent does this in order, from cheap and sparse to expensive and dense, so most of the improvement comes cheaply.

01Definition

Given MoveGen functions ordered by density, hill climb with MoveGen(1) to a local optimum, then continue from there with MoveGen(2), and so on.

02Pseudocode

node ← start
for i ← 1 to n
    moveGen ← MoveGen(i)            # sparse → dense
    node ← HillClimbing(node, moveGen)
return node

03Line by line

node ← start
for i ← 1 to nMoveGens are sorted sparse → dense.
node ← HillClimbing(node, MoveGen(i))Each phase starts where the previous phase stopped.
return nodeA local optimum for the last (densest) neighbourhood.

04Formulas and why they hold

LocalOpt(N₁) ⊉ LocalOpt(N₂)

being stuck in one neighbourhood does not mean being stuck in another

Different moves reach different tours; a denser neighbourhood contains moves the sparse one lacks.

05Why it works, and when it does not

Sparse neighbourhoods are cheap and do most of the work; dense ones are used only near the end, where they escape the sparse operator's traps.

06Properties

completeno
optimalno
timesum of the phases' hill climbs
spaceO(n)

07Traps

  • The course version runs each MoveGen once, in order; some variants restart from MoveGen(1) after any improvement.
  • A phase can make no progress at all: that is fine.
