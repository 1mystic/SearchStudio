Uniform Cost Search

Run it step by step

Uniform Cost Search always expands the cheapest path found so far. With different edge costs it finds the cheapest route, not just the one with the fewest steps.

01Definition

A state-space search problem has a start node S, a goal test, and a MoveGen function that lists the neighbours of a node. The search keeps two lists: OPEN (nodes generated but not yet expanded) and CLOSED (nodes already expanded). Each entry is a node pair (node, parent, value) so the path can be read back through parents. OPEN is ordered by g(N), the cost from S to N. If a cheaper path to a node already seen is found, its parent and g are updated.

02Pseudocode

OPEN ← [(S, nil, 0)] ordered by g
while OPEN not empty
    N ← node with least g;  remove it
    if GoalTest(N): return the path
    move N to CLOSED
    for each child C of N with g' = g(N) + k(N,C)
        new: add (C, N, g') to OPEN
        on OPEN/CLOSED with larger g: update parent and g (reopen if on CLOSED)

03Line by line

OPEN ordered by gg(N) = cost of the best known path from S to N.
N ← least-g node
if GoalTest(N): returnWhen the goal is picked, no cheaper path to it can exist.
g' = g(N) + k(N, C)k is the edge cost.
update a node if g' is smallerReopen it if it was on CLOSED.

04Formulas and why they hold

g(C) = g(N) + k(N, C)

cost so far plus the edge

Paths are extended one edge at a time.

pick argmin g on OPEN

cheapest frontier node first

With non-negative costs this expands nodes in order of their true distance from S.

05Why it works, and when it does not

Optimal for non-negative edge costs; it is Dijkstra's algorithm stopped at the goal. It explores in all directions because it has no idea where the goal is.

07Traps

  • Apply the goal test when the goal is removed from OPEN, not when it is generated.
  • Remember to update g and the parent on cheaper paths.
