Week 6 · Graph search · space saving

A* with upper-bound pruning of OPEN

Run it step by step

OPEN is where A* spends much of its memory. If we already know some solution of cost U, any node whose estimate f = g + h exceeds U cannot be on a cheaper solution (with an admissible h), so it is not worth storing. **Supplementary:** this is the bound used in Zhou and Hansen's space-saving A* variants; it is not in the lecture slides.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Run A* as usual, but when a child C is generated with f(C) = g(C) + h(C) > U, drop it instead of adding it to OPEN. U can be given or obtained cheaply, for instance from greedy best-first search. If OPEN becomes empty without reaching the goal, the quick solution that produced U is returned.

02Pseudocode

U ← cost of a quick solution (greedy by h) or a given bound
OPEN ← [(S, nil, 0)]
while OPEN not empty
    N ← node with least f = g + h;  remove it
    if GoalTest(N): return the path
    move N to CLOSED
    for each child C with g' = g(N) + k(N,C)
        if g' + h(C) > U: discard C  (never enters OPEN)
        else add / update C exactly as A* does
return the quick solution if OPEN empties (it was optimal or h was inadmissible)

03Line by line

U ← greedy solution costAny solution is an upper bound on the optimum.
N ← least f; goal testSame as A*: goal test happens when the node is picked.
if f(C) > U discard CWith admissible h no better path goes through C.
OPEN empty: return the quick solutionOnly happens when U was already optimal, or when h overestimates.

04Formulas and why they hold

discard C when g(C) + h(C) > U

the best possible cost through C is already worse than a known solution

With h ≤ h*, g(C) + h(C) never overestimates the cheapest solution through C, so such a C cannot improve on U.

C* ≤ U

the optimum is at most the bound

U is the cost of a real solution. A bound below C* would wrongly discard every solution; the run then reports failure.

05Why it works, and when it does not

A better bound prunes more: on the 'Dijkstra demo' graph the greedy bound U = 9 keeps peak OPEN at 2 where A* needs 3. The saving is on OPEN only: CLOSED is as large as in A*. Combine with CLOSED-pruning methods (BFHS, SMGS) for real savings.

06Properties

completeyes if U ≥ C*
optimalyes with admissible h and U ≥ C*
timeat most A*'s
spaceOPEN smaller than A*, CLOSED same

07Traps

  • With an inadmissible h, a node with f > U may still lead to a cheaper path, so pruning can lose the optimum (the search then falls back to the quick solution).
  • A bound that is too small yields no solution at all.
  • Nodes with f = U are kept: they may still give a solution of cost exactly U.
