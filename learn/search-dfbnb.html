Depth-First Branch and Bound

Run it step by step

Depth-First Branch and Bound keeps the small memory of depth-first search but still finds the optimal path. It carries a bound U, the cost of the best complete path found so far, and cuts off any branch that already costs at least U.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Explore depth-first. The first path to the goal sets U = its cost. From then on, a path to node N is pruned when g(N) + h(N) ≥ U, because with an admissible h no completion of it can be cheaper than U. Whenever a cheaper goal path is found, U is lowered. When the search ends, the best path found is optimal. Only the current path is stored, so memory is linear in the depth. With the option 'g only' the heuristic is ignored (h = 0): then the pruning test is g(N) ≥ U.

02Pseudocode

U ← ∞;  best ← none
DFBnB(N, g, path):
    if g + h(N) ≥ U: prune; return                 # cannot improve on the best solution
    if GoalTest(N): U ← g;  best ← path;  return   # a better solution
    for each child C of N not on the path, in increasing order of g' + h(C):
        DFBnB(C, g + k(N,C), path + C)
return best

03Line by line

U ← ∞No solution known yet.
go depth-first, nearest children firstOrdering by g + h finds a good U early.
prune if g + h ≥ UThis path cannot beat the best solution.
goal reached with g < U: U ← gA cheaper solution; remember the path.
backtrack until every branch is searched or prunedThe last U is the optimum.

04Formulas and why they hold

prune N when g(N) + h(N) ≥ U

its best possible total is no better than the bound

With h ≤ h* the true cost of any path through N is at least g(N)+h(N), so continuing cannot help.

U ← min(U, g(goal))

tighten the bound at each solution

A smaller U prunes more of the remaining tree.

05Why it works, and when it does not

It needs memory only for the current path, unlike A* whose OPEN list can grow exponentially, and it still returns an optimal path. Its weakness is that, on a graph, it may reach the same state again by many paths. A good first solution (found by ordering children well) makes it prune heavily.

07Traps

  • The first goal found is not the answer: keep searching with the bound.
  • With an inadmissible h the pruning can discard the optimal path; with h = 0 ('g only') it is always safe.
  • A bad child ordering finds a poor U late and prunes little. On the 'Weighted graph' U improves twice (first S–A–C–E–G = 13, then the optimum S–B–E–G = 12) and every later branch is cut by g + h ≥ U.
  • Prune with ≥ U: a path equal to U cannot improve the answer.
  • Unlike A*, the first solution is usually not optimal; the search only stops when every branch is pruned. Use 'g only' to see the bound work without a heuristic: more branches survive.
