Week 6 · Graph search · space saving

Beam Stack Search

Run it step by step

Plain beam search forgets nodes outside the beam and can miss the goal. Beam stack search keeps a small record of what was forgotten: for every layer, the interval of f values it has already covered. When the search runs dry it backtracks and goes after the part of f-space it skipped. **Supplementary:** this is Zhou and Hansen's algorithm; it is not in the lecture slides.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Layer k holds nodes reached with k moves, at most w of them. The beam stack has one item [lo, hi) per layer. Children of layer k go to layer k+1 only if f is in [lo, hi) and f ≤ U. If there are more than w, the w with least f survive and hi becomes the f of the best node dropped. When a layer has no children (dead end or goal), backtrack to the deepest layer with hi < U, set lo ← hi and hi ← ∞, and rebuild that layer from the one above. Ties in f are broken alphabetically, so the intervals are over (f, name) pairs and the search always terminates.

02Pseudocode

U ← cost of a quick solution (greedy) or a given bound
layer 0 ← [S];  beam stack ← [ [lo=−∞, hi=∞) per layer ]
loop
    if a node of the current layer is the goal and g < U: remember it, U ← g
    candidates ← children of the layer with f ≤ U and f in [lo, hi) of the next layer's stack item
    if more than w candidates: keep the w with least f, set hi of that item to the f of the best discarded one
    if the next layer is non-empty: go down one layer
    else BACKTRACK: pop to the deepest layer whose hi < U;  lo ← hi, hi ← ∞;  rebuild that layer
    stop when no layer has hi left to explore
return the best goal found

03Line by line

layer 0 ← [S], stack item [−∞, ∞)
candidates in [lo, hi) with f ≤ UThe stack says which f values this layer still owes us.
keep w best; hi ← f of best droppedWhat was dropped is remembered as the part of f-space not yet searched.
empty layer: backtrack, lo ← hi, hi ← ∞Searches the next slice of f-values at the deepest layer that has one.

04Formulas and why they hold

stored nodes ≤ w · (layers)

each layer holds at most w nodes

The beam width bounds the memory regardless of the graph.

layer k item = [lo_k, hi_k)

f-values already covered up to hi_k

Every dropped node has f ≥ hi_k, so once all slices are searched nothing with f ≤ U is missed; with admissible h the optimum is found.

05Why it works, and when it does not

On the 4×5 grid with w = 2 it stores at most 14 nodes where A* stores 20, at the price of 40 expansions against A*'s 19 (it backtracks 3 times). A wide enough beam makes it behave like A*; w = 1 turns it into depth-first-like backtracking. Memory stays small either way, so it trades time for space.

06Properties

completeyes (with backtracking)
optimalyes with admissible h
timeup to exponential
spaceO(w · depth)

07Traps

  • With w = 1 it can revisit the same node many times.
  • A bound U that is too low prunes the solution; the greedy bound is always safe.
  • The cost equals UCS/A* only when h is admissible; with an inadmissible h it returns the best path it saw, which may not be optimal.
  • Cycles are avoided here by never generating a node that is already on its own path.
