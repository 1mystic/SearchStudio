Week 8 · Planning

Means-ends analysis

Run it step by step

Means-ends analysis (the idea behind Newell and Simon's General Problem Solver) works from differences. Compare the current state with the goal, choose the most important difference, and find an operator that reduces it. If the operator cannot be applied yet, its preconditions become a new sub-goal, solved by the same procedure. The difference table says which operator removes which kind of difference.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Difference table for the blocks world: on(x,y) is removed by stack(x,y); ontable(x) by putdown(x); clear(x) by unstack(z,x) for the block z on x; holding(x) by pickup(x) (x on the table) or unstack(x,y); AE by putdown of the held block. Importance: positional differences first, lower blocks of the goal tower before higher ones (a tower is built from the bottom), then clear, then AE, then holding. Sub-goals are solved in the same importance order. Because MEA never protects facts it has already achieved, a later sub-goal can undo an earlier one: on the Sussman anomaly it keeps destroying and re-making the same facts and the loop check stops it.

02Pseudocode

MEA(state, goal):
    while goal ⊄ state
        d ← the most important difference (goal fact not in state)
        O ← operator that adds d            // from the difference table
        MEA(state, pre(O))                  // sub-goal: make O applicable
        if O is not applicable: fail
        state ← apply(O, state)
    return

04Formulas and why they hold

difference = goal − state

goal facts not currently true

These are exactly what remains to be achieved.

05Why it works, and when it does not

It is the first goal-directed planner: instead of blind search it only considers operators relevant to a difference. Its failure on interacting goals motivates goal protection, partial-order planning and Graphplan.

07Traps

  • MEA is not complete: it does not protect earlier achievements, so it can undo its own work and cycle (the Sussman anomaly). Run example plan-sussman to watch it fail and plan-reverse to watch it succeed.
  • The result depends on the importance ordering and on the difference table; a different table can succeed where this one fails.
  • A sub-goal may clobber a fact achieved earlier: after each operator, recompute all differences.
