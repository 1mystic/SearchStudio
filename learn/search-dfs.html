Depth First Search

Run it step by step

Depth First Search goes as deep as possible along one path before backing up. It needs little memory but can wander far from a nearby goal.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A state-space search problem has a start node S, a goal test, and a MoveGen function that lists the neighbours of a node. The search keeps two lists: OPEN (nodes generated but not yet expanded) and CLOSED (nodes already expanded). Each entry is a node pair (node, parent, value) so the path can be read back through parents. DFS treats OPEN as a stack: new children go to the front.

02Pseudocode

OPEN ← [(S, nil, 0)];  CLOSED ← [ ]
while OPEN not empty
    (N, parent, d) ← head(OPEN);  remove it
    if GoalTest(N): return the path
    CLOSED ← (N, parent, d) : CLOSED
    children ← MoveGen(N) minus nodes on OPEN or CLOSED
    OPEN ← [(C, N, d+1) for C in children] ++ OPEN     # prepend = stack
return failure

03Line by line

OPEN ← [(S, nil, 0)]
(N, parent, d) ← head(OPEN)Newest entry first (stack).
if GoalTest(N): return path
CLOSED ← (N, parent, d) : CLOSED
OPEN ← children ++ OPENPrepend = stack = depth first.

04Formulas and why they hold

space ≈ b · m

branching factor times maximum depth

Only the current path and the siblings along it are stored.

05Why it works, and when it does not

Memory-light, but neither optimal nor guaranteed to finish on infinite or very deep spaces.

06Properties

completefinite graphs only
optimalno
timeO(b^m)
spaceO(b·m)

07Traps

  • The path found depends heavily on MoveGen order.
  • Do not confuse the order children are pushed with the order they are expanded.
