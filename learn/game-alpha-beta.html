Week 7 · Game playing

Alpha-Beta pruning

Run it step by step

Alpha-beta gives the same answer as minimax while skipping parts of the tree that cannot change the decision. If you already know a move gives you 3, you can stop examining another move as soon as you see the opponent can hold you to 2 there.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Pass a window (α, β) down the tree. α is the best value MAX is already guaranteed, β the best value MIN is guaranteed. At a MAX node raise α; at a MIN node lower β; as soon as α ≥ β, prune the remaining children.

02Pseudocode

AlphaBeta(N, α, β):
    if N is a leaf: return e(N)
    if N is MAX:
        for each child C: α ← max(α, AlphaBeta(C, α, β)); if α ≥ β: prune the rest (β cut-off)
        return α
    if N is MIN:
        for each child C: β ← min(β, AlphaBeta(C, α, β)); if α ≥ β: prune the rest (α cut-off)
        return β
call AlphaBeta(root, −∞, +∞)

04Formulas and why they hold

MIN above will never allow a value ≥ β, and MAX above already has α: nothing in this subtree can affect the root.

best case ≈ b^(d/2) leaves

with perfect move ordering

Good ordering lets each MIN node be refuted by its first child, effectively doubling the search depth for the same work.

05Why it works, and when it does not

Always returns the minimax value. How much it prunes depends on move ordering: try the 'best first' and 'worst first' settings.

06Properties

completeyes
optimalsame value as minimax
timeO(b^(d/2)) best, O(b^d) worst
spaceO(b·d)

07Traps

  • Pruned subtrees are never evaluated: count leaves carefully.
  • The value returned at a pruned node is a bound, not an exact value; only the root's value is exact.
