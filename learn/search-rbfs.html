Recursive Best-First Search

Run it step by step

Recursive Best-First Search behaves like A* but stores only the current path. When the path it is exploring becomes worse than the best alternative elsewhere, it remembers how good that path turned out to be and switches.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

At each node, expand the child with the lowest backed-up value F while it stays below a limit (the best alternative higher up). When it exceeds the limit, return and replace the child's F by the best value found below it.

02Pseudocode

RBFS(N, F(N), limit):
    if GoalTest(N): return SUCCESS
    children ← MoveGen(N) not on the current path
    for each child C: F(C) ← max(g(C) + h(C), F(N))     # inherit a backed-up value
    loop
        best ← child with least F;  if F(best) > limit: return FAIL, F(best)
        alt ← second least F (∞ if none)
        result, F(best) ← RBFS(best, F(best), min(limit, alt))
        if result = SUCCESS: return SUCCESS
call RBFS(S, h(S), ∞)

03Line by line

F(child) ← max(g + h, F(parent))A child inherits its parent's backed-up value if that is larger.
best ← child with least F
if F(best) > limit: return F(best)Report how good this subtree really is, so the parent can compare it with alternatives.
recurse with limit = min(limit, second-best F)Explore best until it looks worse than the runner-up.

04Formulas and why they hold

F(N) = backed-up minimum of f over N's explored subtree

the best f value seen below N

Lets RBFS return to a forgotten subtree knowing exactly how promising it was.

05Why it works, and when it does not

Linear space and optimal with admissible h. It may re-expand the same nodes many times when the best path keeps switching.

07Traps

  • The limit passed down is the second-best F, not the parent's f.
  • Keep backed-up values; recomputing g + h throws the information away.
