Multi-arm plan scheduling (makespan)

Run it step by step

A sequential plan does one action per time step with a single arm. If the robot has k arms, some actions can happen at the same time, and what matters is the makespan: the number of time steps until the goal holds. The question is which actions may overlap. An action can run only when its preconditions hold, and two arms must not work on the same blocks at once. Moves that share no block are independent and can run in parallel; moves that share a block must keep the order the plan gave them.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A move is a pick-up (pickup or unstack) together with the put-down (putdown or stack) that follows it: the arm is busy for both steps. Move B depends on an earlier move A if they mention a common block. A schedule gives every move a start step and an arm such that dependent moves do not overlap, no arm is asked to do two things at once, and each action's preconditions hold when it runs. The makespan is the number of time steps used. (Scheduling a plan onto several arms is not part of the course notes: this is an extension of the course's single-arm STRIPS operators.)

02Pseudocode

plan ← plan from another planner;  group each pick-up with the put-down that follows it into one move
move B must wait for every earlier move A that shares a block with it
for t = 1, 2, 3, ...
    for each free arm, in order:
        take the first not-yet-started move (in plan order) whose earlier moves have all finished
        start it on this arm: pick-up at t, put-down at t + 1
makespan ← last time step used

03Line by line

group pick-up and put-down into movesThe arm is occupied while it holds a block, so the two actions belong together.
a move depends on earlier moves sharing a blockThey change the same facts (on, clear, holding), so their order matters.
each time step, give every free arm a ready moveReady means all moves it depends on have finished.
makespan = last time step usedCompare with the sequential plan length, which is the makespan with one arm.

04Formulas and why they hold

makespan ≤ sequential length; makespan ≥ longest dependency chain

parallel arms never hurt, and cannot beat the chain of forced orderings

At every step at least one ready move can run, so no step is wasted; but moves that depend on each other must follow one another whatever the number of arms.

with k = 1 arm: makespan = sequential length

one arm does one action per step

A sanity check: with one arm the schedule collapses to the original plan.

05Why it works, and when it does not

Plans are not only about getting to the goal: in practice time matters. Splitting the work over several arms shows which parts of a plan are really independent. It also shows why some plans cannot be sped up: the Sussman anomaly is one chain of dependent moves, so extra arms do not help.

06Properties

completeyes (always produces a valid schedule)
optimalno (greedy list scheduling)
timeO(m²)
spaceO(m)

07Traps

  • Shared blocks are what link moves: moving C and moving B look separate, but if B must land on C, the second move waits for the first.
  • More arms do not always help. The longest chain of dependent moves is a lower bound on the makespan.
  • The plan itself is not changed, only when its actions run. A different plan (for example from goal-stack planning) can leave more room for parallel work than the shortest plan.
