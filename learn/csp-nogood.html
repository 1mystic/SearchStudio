Week 12 · Constraint processing · lookback

Nogood recording

Run it step by step

Backtracking can discover the same dead end again and again under different irrelevant assignments. Nogood recording is a look-back method that remembers a dead end in a general form so it is never rediscovered.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A nogood is a partial assignment that cannot be extended to a solution. When Xᵢ has no value left, the values of the variables in its conflict set form a nogood. Later, any assignment that contains a stored nogood is rejected immediately.

02Pseudocode

Nogood-BT(i):
    conf(Xᵢ) ← { }
    for each value a in D(Xᵢ)
        if some stored nogood ⊆ assignment + {Xᵢ = a}: add its other variables to conf(Xᵢ); skip a   # pruned by a nogood
        else if a clashes with an assigned Xⱼ: add Xⱼ to conf(Xᵢ); skip a
        else assign Xᵢ = a; if Nogood-BT(i + 1) succeeds: return success
             else add the failed child's conflict set − {Xᵢ} to conf(Xᵢ)
    store nogood { Xⱼ = value(Xⱼ) : Xⱼ ∈ conf(Xᵢ) }         # unless a smaller stored nogood already covers it
    return failure                                            # chronological: go back to Xᵢ₋₁

03Line by line

try a value of Xᵢ
contains a stored nogood?Reject at once and note which nogood did it.
clash with an earlier Xⱼ?Record Xⱼ in the conflict set.
no value leftBuild the nogood from the conflict set and store it.
backtrackChronologically here; combine with backjumping for both effects.

04Formulas and why they hold

nogood = { Xⱼ = vⱼ : Xⱼ ∈ conf(Xᵢ) }

the culprits and their current values

The values in conf(Xᵢ) alone already exclude every value of Xᵢ, so any assignment containing them is hopeless, whatever else it says.

05Why it works, and when it does not

Small nogoods prune big parts of the tree. In the example 'Nogood recording' the single nogood {A=r} found at D rejects three later values (C=z, B=y, B=z) without any search.

06Properties

completeyes
optimaln/a
timeO(dⁿ) worst case, ≤ backtracking
spaceO(number of nogoods)

07Traps

  • Try example 'Nogood recording': the dead end at D is stored as {A=r} and later rejects C=z, B=y and B=z without search (10 nodes against 24 for plain backtracking). Nogood recording is chronological, so it still goes back one level at a time; CBJ jumps but forgets, nogoods remember but do not jump.
  • A nogood only prunes assignments that contain ALL of its variable-value pairs.
  • Storing every nogood costs memory; real systems bound the size or the number of nogoods.
  • Nogoods whose variables are already covered by a smaller stored nogood are not stored again. This subsumption test is **supplementary**.
