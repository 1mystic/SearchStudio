Model-based diagnosis

Run it step by step

When a device misbehaves, model-based diagnosis asks: which components, if broken, would explain what we observe? It uses models of how each component should behave and looks for contradictions.

01Definition

Assume a set of components works and propagate values through their models. A contradiction with an observation means that set cannot all be working: it is a conflict set. A diagnosis is a minimal set of components that intersects every minimal conflict.

02Pseudocode

for each set S of components assumed OK
    propagate values using only the models of S (forward and backward through + and ×)
    if some wire gets two different values: S is inconsistent
conflicts ← minimal inconsistent sets
diagnoses ← minimal sets of components that intersect every conflict (minimal hitting sets)

03Line by line

propagate with every component assumed OKFind the first contradiction.
find minimal conflictsSmallest sets of components whose joint correctness contradicts the observations.
minimal hitting setsEach must contain at least one component from every conflict.

04Formulas and why they hold

diagnosis D: D ∩ C ≠ ∅ for every conflict C, D minimal

blame at least one component in every conflict

If any conflict had no faulty member, the contradiction would remain.

05Why it works, and when it does not

The polybox has conflicts {M1, M2, A1} and {M1, M3, A1, A2}, giving the diagnoses {M1}, {A1}, {M2, M3}, {M2, A2}.

06Properties

completeyes (all minimal diagnoses)
optimaln/a
timeexponential in components (direct form)
spaceO(conflicts)

07Traps

  • A conflict lists the components used to derive the contradiction, not just the one producing the wrong output.
  • Diagnoses are minimal: supersets also explain the symptoms but are less likely.
