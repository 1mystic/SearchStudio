Week 8 · Planning

Partial Order Planning

Run it step by step

A planning problem gives an initial state, a goal and operators described in STRIPS form: each operator has preconditions, an add list and a delete list. In the blocks world the operators are pickup, putdown, stack and unstack, and AE means the arm is empty. Partial Order Planning searches the space of plans instead of states, adding steps and orderings only when it must.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

A partial plan has steps, ordering constraints, causal links (A achieves p for B) and open preconditions. Repeatedly support an open precondition with an existing or new step, then resolve threats (a step that deletes p and could fall between A and B) by ordering it before A (demotion) or after B (promotion). Backtrack on failure.

02Pseudocode

plan ← {Start, Finish}, Start < Finish, agenda ← goal preconditions of Finish
while agenda not empty
    (p, S) ← pick an open precondition
    choose an achiever A: an existing step that adds p and may precede S, or a new step from the operators
    add causal link A →p→ S and ordering A < S;  if A is new: add A's preconditions to the agenda
    for every step K that deletes p and could fall between A and S (a threat):
        demote (K < A) or promote (S < K), keeping the orderings acyclic
    if no choice works: backtrack
return any linearisation of the steps

03Line by line

Start < FinishStart's effects are the initial state; Finish's preconditions are the goal.
pick an open preconditionHere: the most constrained one first.
add a causal link from an achieverExisting steps first, then new steps.
resolve threatsDemotion or promotion, keeping the order acyclic.
no open preconditions → doneAny linearisation of the steps is a valid plan.

04Formulas and why they hold

threat: K deletes p and possibly A < K < B for link A →p→ B

a step that could undo a protected condition

Ordering K outside the interval keeps every causal link safe, which guarantees the plan works.

least commitment

order steps only when forced

Avoids the interaction problems that make linear planners fail on the Sussman anomaly.

05Why it works, and when it does not

Finds the optimal 6-step plan for the Sussman anomaly by interleaving subgoals; the search can be expensive.

06Properties

07Traps

  • Check threats for new links and for new steps.
  • Never order a step before Start or after Finish.
