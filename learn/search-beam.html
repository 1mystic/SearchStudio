Beam Search

Run it step by step

Beam search is breadth-first search on a diet: at every level it keeps only the w most promising nodes by h and forgets the rest. A wider beam is safer, a narrower one is cheaper.

01Definition

Level by level, generate the children of every node in the beam, discard those seen before, and keep the w with the smallest h. Succeed when the goal enters the beam; fail when no new children remain.

02Pseudocode

OPEN ← [start]
while goal not in OPEN
    children ← MoveGen of every node in OPEN, minus nodes seen before
    if children is empty: return failure
    OPEN ← the w best of children by h
return the goal's path

03Line by line

OPEN ← [start]
children ← MoveGen of every node in the beamNodes seen earlier are dropped (graph search).
OPEN ← w best children by hEverything else is discarded for good: beam search cannot backtrack to it.
goal in OPEN → done

04Formulas and why they hold

memory ≤ w per level

the beam width bounds the frontier

That is the whole point: predictable memory. w = 1 is hill climbing that may move uphill; w = ∞ is breadth-first search.

05Why it works, and when it does not

Keeps several alternatives alive, so one bad estimate does not end the search, but anything outside the beam is lost forever.

06Properties

completeno
optimalno
timeO(w · b · d)
spaceO(w · d)

07Traps

  • Beam search is incomplete: the only path to the goal can fall outside the beam.
  • Ties in h decide which nodes survive.
