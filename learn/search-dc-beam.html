Week 6 · Graph search · space saving

Divide and Conquer Beam Search

Run it step by step

Beam search bounds memory by keeping only w nodes per layer, but then the path cannot be read from parent pointers without storing every layer. Divide and Conquer Beam Search keeps one extra node instead: the middle node of the best path found, the relay. Each half is then a smaller beam search of the same kind. **Supplementary:** this is Zhou and Hansen's divide-and-conquer beam search; the course covers beam search and divide-and-conquer frontier search separately.

⎙Tip: press Ctrl+P to print or save this page as PDF.

01Definition

Run beam search from S to T: generate the children of the layer, drop those with f = g + h above the bound U, drop duplicates found in the current or previous layer, and keep the w best by f. Continue until the layers run out, remembering the best goal. Repeat the run with every node of layer ⌊L/2⌋ acting as a relay that its descendants inherit. The best goal's relay R splits the problem into S→R (cost g(R)) and R→T (cost C − g(R)); solve both recursively with h = 0 and their exact costs as bounds. If a half cannot be re-found at width w, the width is doubled for that half until it can.

02Pseudocode

DCBS(S, T, U, w):
    run beam search from S to T, layer by layer, keeping the w best nodes by f in each layer
        (nodes with f > U are never generated; only the current and previous layers are stored)
    if no goal was reached: fail
    if the path has ≤ 1 move: return [S, T]
    run it again, each node on layer ⌊L/2⌋ becoming its own relay, passed on to its descendants
    R ← the relay of the best goal, with g(R)
    return DCBS(S, R, g(R), w) ++ DCBS(R, T, C − g(R), w)       # drop the repeated R

03Line by line

beam search S→T with width wLayer by layer, only the w best nodes by f survive; nodes beyond w are cut.
rerun marking layer ⌊L/2⌋ nodes as relaysThe same beam is rebuilt, so the same best goal is found, now with a relay.
R ← relay of the best goalA node halfway (by moves) along the best path found.
solve S→R and R→TSmaller beam searches with exact cost bounds; their paths are joined.

04Formulas and why they hold

|beam| ≤ w, stored nodes ≤ 3w

the new layer plus the two kept layers

At most w nodes survive in each layer and only the current and previous layers are kept for duplicate detection, so memory does not grow with depth.

C = g(R) + cost(R→T)

the path found splits at the relay into two parts

Each part of the path found is itself a path of the stated cost, so joining the solved halves gives a path of cost C. It is optimal only if beam search found an optimal path.

05Why it works, and when it does not

Shows how to recover the path from a search that stores almost nothing. A very wide beam behaves like BFHS and finds the optimum; a narrow beam may cut the only route, and then the search falls back to the quick solution or reports failure.

06Properties

completeno (yes when w ≥ number of nodes)
optimalno for small w, yes for a wide beam with admissible h
time≈ 2 × beam search
spaceO(w)

07Traps

  • Beam search is incomplete: with a small w the beam can lose every route to the goal. Then DC beam search returns the greedy quick solution that gave U, or says it found nothing.
  • The halves are searched with h = 0 (h aims at T, not at the relay), so a narrow beam may need widening to re-find a half.
  • A wider beam is not always cheaper in memory terms: peak storage grows with w.
