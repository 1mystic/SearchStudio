Add an algorithm or an example

The library is the algorithms/ folder. Add a file, run the build, and it appears on the site with its own learn page and studio entry.

Project layout

search-studio/
├── algorithms/          one file per algorithm, grouped by family
│   ├── _template.js     copy this to start (files starting with _ are skipped)
│   ├── search/          bfs.js, dfs.js, dfid.js, ucs.js, best-first.js, a-star.js
│   └── tsp/             nearest-neighbour.js, greedy.js, savings.js, …
├── examples/            one JSON file per built-in problem
├── src/
│   ├── core/            registry, problem model, search engine, TSP helpers
│   ├── ui/              stage renderer and the app
│   ├── pages/           home, guide, about, contribute (plain HTML)
│   └── styles/          studio.css
├── tools/
│   ├── build.mjs        scans the folders and builds the site
│   └── test.mjs         runs every algorithm on every example
├── index.html           generated: the site, loading files from the folders
└── dist/search-studio.html   generated: the whole site in one file

Add an algorithm in four steps

  1. Copy algorithms/_template.js to algorithms/<family>/<name>.js.
  2. Fill in the metadata (id, name, family, problem), the learn block and run.
  3. Run node tools/build.mjs. The build loads every file, checks that it registers, runs it on the examples, and regenerates index.html, the manifest and the single-file build. Use node tools/build.mjs --watch while you work.
  4. Open index.html (or serve the folder with npx serve) and find your algorithm in the library.

The algorithm file

Studio.register({
  id: "tsp-my-method",            // unique, used in links: #algo-tsp-my-method
  name: "My method",
  family: "TSP · local search",   // the library groups by this
  problem: "tsp",                 // tsp, graph, game, andor, planning, rules, csp, linedrawing, circuit, alignment
  week: 3,                        // course week 1–11: places it on the course map
  order: 200,                     // position inside the family
  summary: "One sentence for the library card.",
  pseudocode: `...`,
  complexity: "O(n²) per step",
  learn: {
    intro: "Plain-language introduction.",
    definition: "Precise definition.",
    steps: [["pseudocode line", "what it does and why"]],
    formulas: [{ f: "formula", read: "in words", why: "why it holds" }],
    why: "When it works and when it fails.",
    traps: ["Common mistake"],
    props: { complete: "no", optimal: "no", time: "…", space: "…" }
  },
  params: [
    { key: "start", label: "Start city", type: "city", default: P => P.ids[0] },
    { key: "w", label: "Beam width", type: "int", default: 2 },
    Studio.seedParam(1)
  ],
  run(P, params) {
    // P.ids, P.d(a, b), P.cost(tour) for TSP; P.adj, P.h, P.start, P.goal for graphs
    return { steps: [ /* one object per snapshot */ ], result: { tour, cost } };
  }
});

What a step can contain

fieldshapeshown as
captionstringthe yellow sentence under the stage (required)
nodes{ A: { state, badge } }node colours; states: plain, current, open, closed, visited, path, goal, start
edges[{ u, v, state, label }]edges; states: faint, tour, path, candidate, added, removed, rejected, alt, tree, pheromone
table{ title, columns, rows, rowStates }the working table; row states: ok, bad, warn, cur, dim
lists[{ label, items: [{ text, state }] }]OPEN / CLOSED style rows
stats[{ label, value, state }]small figures under the graph
chart{ kind: "walk" | "drops" | "bars" | "pie", … }a small chart beside the table

Helpers in src/core do most of the work: Studio.search.run for OPEN/CLOSED searches, Studio.tsp.moveGens for 2-city, 2-edge, Or-opt and 3-edge neighbourhoods, Studio.tspSteps.hillClimb for traced hill climbing, Studio.tsp.crossovers for every crossover, and Studio.rng(seed) for repeatable randomness.

Add an example problem

Drop a JSON file into examples/ and rebuild. In the studio, Export problem gives you a file in exactly this shape.

{ "id": "graph-my-maze", "type": "graph", "name": "My maze",
  "note": "One line shown under the problem selector.",
  "nodes": [{ "id": "S", "x": 0, "y": 0, "h": 4 }, …],
  "edges": [["S", "A", 2], …], "start": "S", "goal": "G", "directed": false }

{ "id": "tsp-my-cities", "type": "tsp", "name": "My cities",
  "cities": [{ "id": "A", "x": 1, "y": 2 }, …],
  "matrix": [[0, 12, …], …] }          // optional: without it, 10 × Euclidean distance

Checklist before you share

  • node tools/test.mjs passes: every step has a caption, edges and nodes exist, tours are permutations with correct costs.
  • Ties are broken the course's way (alphabetically) or a setting says otherwise.
  • The learn block explains every formula you use and at least one trap.
  • Random choices go through Studio.rng(seed) so runs repeat exactly.
