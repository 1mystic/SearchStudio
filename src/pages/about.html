About Search Studio

A study companion for search methods: the algorithms of state-space search, informed search and stochastic optimisation, traced exactly the way they are traced by hand.

Why it exists

Search algorithms are easy to describe and surprisingly easy to trace wrongly: a missed tie-break, a child added twice, a forgotten closing edge, a savings pair merged that should have been refused. Seeing every step, with the working table and the OPEN and CLOSED lists side by side, makes those mistakes visible.

What it covers

  • State-space search: Breadth First, Depth First, Depth First Iterative Deepening, Uniform Cost, Best First and A* (with weighted A*).
  • Travelling salesperson, constructive: Nearest Neighbour, Greedy, Savings, and brute force as the exact reference.
  • Perturbation and local search: 2-city exchange, 2-edge exchange, Or-opt, 3-edge exchange, Variable Neighbourhood Descent, Beam Search, Tabu Search, Iterated Hill Climbing, Random Walk, Simulated Annealing.
  • Population methods: Genetic Algorithm with cycle, PMX, order, alternating-edges, heuristic and ordinal crossover, and Ant Colony Optimisation.

Notation

The site follows the notation of AI: Search Methods for Problem Solving (Prof. Deepak Khemani, IIT Madras) and his book A First Course in Artificial Intelligence: MoveGen and GoalTest, OPEN and CLOSED as lists of node pairs, path representation for tours, the sigmoid acceptance rule for simulated annealing, and the course's crossover conventions. It is an independent study aid and is not affiliated with or endorsed by IIT Madras.

How results are checked

Every algorithm is run against every example and against random problems on each build. Tours must be permutations whose reported cost matches a recomputation; paths must run from start to goal with the reported cost. On the six-city instance the results are compared with an independent Python implementation (optimum 224, Nearest Neighbour 264, Greedy 238, Savings 224, and so on).
